# WorkFlow — поддержка без потерь

Демо-интерфейс службы поддержки по макету из Figma: публичные страницы, вход, обзорная панель, список и карточка заявки, профиль оператора. Данные отдаются серверными API-ручками Nuxt (хранилище в памяти).

## Стек

- **Nuxt 4** (SSR), Vue 3, TypeScript

## Запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на `http://localhost:3000`.

## Демо-вход

В демо-режиме пользователь уже авторизован как **Анна Ковалёва, оператор**, поэтому `/dashboard`, `/requests` и `/profile` доступны сразу.

Чтобы проверить страницу входа:

1. Выйдите через меню пользователя или кнопку в профиле.
2. Откроется `/login`; введите любой корректный e-mail и пароль от 4 символов.
3. После входа произойдёт возврат на защищённую страницу из параметра `redirect`.

Регистрация в демо не реализована — показывается поясняющее сообщение.

## Маршруты

| Путь | Описание |
| --- | --- |
| `/` | Лендинг: hero с графикой Octagon, 3 шага, возможности, FAQ |
| `/login` | Вход с валидацией и показом пароля |
| `/dashboard` | Обзор: 4 показателя и последние заявки |
| `/requests` | Список заявок: поиск, фильтры, сортировка, пагинация |
| `/requests/:id` | Карточка заявки: описание, комментарии, история, параметры |
| `/profile` | Профиль: данные, настройки интерфейса, выход |

## Возможности

### Данные и API (уровень 2)

- Список и карточка заявки получают данные с API: `GET /api/requests`, `/api/requests/:id`, `/api/users`, `/api/customers`, `/api/categories`, `/api/stats`.
- Fetching через `useFetch`/`useAsyncData` с SSR; преобразование API-данных в доменные модели — в одном месте (`app/utils/apiMappers.ts`).
- TypeScript-типы API-моделей в `shared/types/api.ts`, без `any`.
- Поиск с debounce (300 мс) — запрос не уходит на каждый символ.
- Фильтры, сортировка и пагинация полностью через query-параметры; состояние восстанавливается по прямой ссылке.
- Skeleton loading по реальному статусу загрузки, empty state при отсутствии результатов, error state с кодом ответа и кнопкой «Повторить» (`refresh()`); отдельные сообщения для 429 и 500.
- Устойчивость к данным: заявка без названия → «Без названия», неизвестный клиент/категория → fallback, длинные строки обрезаются.

### Список заявок

- 25 заявок на сервере, по 12 на страницу, серверная фильтрация и сортировка.
- Поиск по номеру, теме, клиенту и исполнителю.
- Фильтры по статусу и приоритету, фильтр по исполнителю, сортировка.
- Все параметры синхронизируются с URL: `q`, `status`, `priority`, `assignee`, `sort`, `page`. Ссылкой можно поделиться.
- Кнопка сброса фильтров и переход в карточку по клику на строку или карточку.

### Заявка

- Статус, приоритет, клиент, категория, SLA и признак просрочки.
- История событий (создание, назначение, смена статуса, комментарии).
- Состояния загрузки и ошибки, отдельный экран «заявка не найдена».
- Создание новой заявки через модальное окно с валидацией — `POST /api/requests`.


## Структура проекта

```text
app/
  assets/css/main.css        дизайн-токены макета (--octagon-*), тема, анимации
  components/                UI-компоненты и блоки страниц
  composables/               useDirectories (справочники), useDebounce, auth, focus trap
  layouts/                   default (app) и public (лендинг/вход)
  middleware/auth.global.ts  защита приватных маршрутов
  pages/                     страницы приложения
  types/                     доменные типы
  utils/                     apiMappers (API → доменные модели), форматирование
  error.vue                  кастомная страница 404/500
server/
  api/                       requests (GET/POST, :id), users, customers, categories, stats
  utils/                     db (хранилище в памяти), priority
shared/
  types/api.ts               TypeScript-модели API (контракт клиент ⇆ сервер)
  utils/due.ts               SLA-сроки (общее для клиента и сервера)
public/images/               графика из макета (octagon-hero.png)
nuxt.config.ts               шрифты, head, transitions, tailwind vite-плагин
```
